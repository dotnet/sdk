# Uninstall commands no longer accept --source

Dotnetup no longer supports the `--source` option for uninstall commands.
Global.json-based install specs are managed through `global.json` instead.

## Version introduced

Dotnetup 0.3.0-preview.2.

## Previous behavior

Uninstall commands accepted `--source` to filter install specs for removal:

| Value | Install specs selected |
| --- | --- |
| `explicit` | Specs created by command-line install requests. |
| `migration` | Specs created when migrating existing installations. |
| `globaljson` | Specs associated with a `global.json` file. |
| `all` | Specs from all sources. |

When omitted, uninstall selected command-line and migration install specs.

## New behavior

`dotnetup uninstall`, `dotnetup sdk uninstall`, and `dotnetup runtime uninstall`
no longer accept `--source`. They remove matching command-line and migration
install specs together. Global.json-based install specs remain controlled by their
`global.json` files. An installation stays installed if another install spec
still needs it.

## Reason for change

Simplify the uninstall command and keep `global.json` as the source of truth for global.json-based install specs.

## Recommended action

Remove the `--source` option from uninstall commands.

To change or remove a global.json-based install spec, edit `sdk.version` or remove
that property from its `global.json` file. Delete the file only if it is no longer needed.
Use `dotnetup list` to find the corresponding repository path and any other
install specs keeping an installation installed.
